## 📝 五、关键设计决策

### 5.1 架构设计原则

1. **事件驱动**: 所有模块通过EventBus通信,避免直接依赖
2. **数据驱动**: 行为/互动/地点等核心数据由JSON配置,易于扩展
3. **状态集中**: 全局状态由StateManager统一管理,支持快照/回滚
4. **分层解耦**: 严格遵循7层架构,上层依赖下层,下层不知上层

### 5.2 核心技术选型

| 技术点 | 选择 | 理由 |
|-------|------|------|
| **模块化方案** | ES6 Module | 原生支持,兼容性好 |
| **状态管理** | 自研StateManager | 游戏场景特化,支持快照 |
| **通信机制** | EventBus(发布订阅) | 解耦模块,易于扩展 |
| **数据存储** | JSON配置+内存Map | 快速读写,易于调试 |
| **AI决策** | 效用函数(Utility AI) | 灵活性高,易于调优 |

### 5.3 性能优化策略

1. **路径缓存**: C1血缘关系路径缓存,避免重复计算
2. **增量更新**: 只刷新变化的UI组件
3. **批量决策**: D1支持多角色并行决策
4. **懒加载**: G3人生面板按需加载历史数据
5. **事件合并**: A2事件总线支持批量处理

### 9.2 术语表

| 术语 | 定义 |
|------|------|
| **个体AI人生** | NPC从出生到死亡的完整生命周期,包括成长、婚配、生育、技能学习、社交互动 |
| **效用函数(Utility AI)** | 基于多维度评分选择最优行为的AI决策方法 |
| **事件总线(EventBus)** | 模块间通信的中介,支持发布/订阅模式 |
| **状态快照(Snapshot)** | 游戏状态的完整拷贝,用于存档/回滚 |
| **数据驱动(Data-Driven)** | 核心逻辑由外部数据配置,代码只负责解释执行 |
