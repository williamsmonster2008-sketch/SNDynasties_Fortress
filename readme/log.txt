## ID系统统一化修复计划

### 问题诊断

**当前数据流：**
```
FamilyNetworkService生成数据
  ↓ (使用characterId: char_unit_xxx_xxx)
bloodRelations存储关系
  ↓
Character构造函数
  ↓ (错误：生成新id，导致双ID)
角色拥有两个ID: characterId(旧) ≠ id(新)
  ↓
UI查询关系
  ↓ (使用新id查询)
getKinship查询bloodRelations
  ↓ (bloodRelations使用characterId)
❌ ID不匹配，查询失败
```

**根本原因：**
Character构造函数同时维护两个ID（characterId和id），但bloodRelations只认characterId，UI查询时用id，导致匹配失败。

### 解决方案

**废除双ID系统，统一使用一个ID**

**修改位置：** `character_module.js` 约50-60行

**当前代码（错误）：**
```javascript
this.characterId = config.characterId || config.id || Utils.String.generateId();
this.id = config.id || this.characterId;
```

**修改为（正确）：**
```javascript
this.id = config.characterId || config.id || Utils.String.generateId();
this.characterId = this.id; // 统一：两个字段指向同一个ID
```

### 为什么这样修改

1. **FamilyNetworkService生成characterId在前**
   - buildFamilyUnits() → 生成完整的characterId
   - 这个ID已经在bloodRelations中作为关系键使用

2. **Character对象创建在后**
   - 接收config.characterId
   - 应该直接使用这个ID，而不是生成新的

3. **统一ID后的效果**
   - 角色只有一个ID
   - bloodRelations和UI都用同一个ID
   - 不需要ID转换逻辑
   - 查询直接匹配成功

### 影响范围

**只需修改一个文件：** `character_module.js`

**其他文件不需要改动：**
- ✅ FamilyNetworkService - 继续生成characterId
- ✅ bloodRelations - 继续使用characterId作为键
- ✅ UI查询 - 会自动使用统一的ID
- ✅ getKinship - 不需要ID转换

### 预期效果

修改后刷新页面：
- 角色的id和characterId相同
- 人际关系正常显示（不再是"暂无关系"）
- 家族谱系正常显示
- 姻亲称谓正确计算

### 回滚方案

如果修改后有问题，只需恢复这两行代码即可。

### ⚠️ 当前发现的问题（待修复）

#### 问题1：不同generation共用同一个辈分字
**现象：**
```
曾祖辈：李礼机（G1）
祖父辈：李礼礼（G2）、李礼朗（G2）、李礼毅（G2）
```
所有世代都用了"礼"作为辈分字。

**可能原因：**
- `generation` 参数传值错误
- `_getGenerationChar()` 的 index 计算有误
- 辈分序列分配有问题

**待诊断：**
需要在 `_getGenerationChar()` 开头添加日志：

```javascript
console.log(`🔍 获取辈分字: 家族=${familyName}, 阶层=${socialClass}, 世代=${generation}`);
```

---

#### 问题2：跨阶层错误借用名字
**现象：**
```
刘菩萨奴 - 刘(非胡族姓) + 菩萨奴(胡族名)
```

**原因：**
`_getNameFromPool()` 在找不到对应阶层名字时，会遍历其他阶层借用，错误地使用了胡族名字。

**修复方案：**
删除跨阶层借用逻辑，改为直接返回降级默认值：
```javascript
if (!namePool || namePool.length === 0) {
  console.warn(`⚠️ 未找到${socialClass}/${gender}的名字池，使用默认名字`);
  return genderKey === 'male' ? '明' : '华';
}
```

---

#### 问题3：辈分字与名字相同
**现象：**
```
李礼礼 - 辈分字"礼" + 名字"礼"
```

**修复方案：**
在 `generateName()` 中生成单字名后添加去重检查：
```javascript
let singleName = this._getNameFromPool(socialClass, gender);

// 去重检查（最多尝试5次）
let attempts = 0;
while (singleName === generationChar && attempts < 5) {
  console.warn(`⚠️ 辈分字与名字重复，重新生成`);
  singleName = this._getNameFromPool(socialClass, gender);
  attempts++;
}

// 强制修改
if (singleName === generationChar) {
  singleName = gender === '男' ? '之' : '华';
}
```

### 💡 命名系统设计总结

**命名格式：**
- 门阀士族/寒门士人/豪强地主：姓 + 辈分字 + 名
- 自耕农/佃农：姓 + 辈分字 + 名
- 胡族：姓 + 名（无辈分字）

**辈分字分配：**
- 士族使用 `eliteGenerationNames`（15组高雅序列）
- 平民使用 `commonGenerationNames`（8组朴实序列）
- 每个家族分配一组序列，不重复使用
